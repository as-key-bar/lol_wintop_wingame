# Phase 2 ロードマップ

承認済みの計画（2026-11-11）と、その進捗です。詳細な現状と既知の課題は [HANDOFF.md](./HANDOFF.md) を参照してください。

## 方針

情報の取得方法によって難しさが大きく違うため、2つの段階に分けて進めます。

- **Phase 2A：YouTube 動画の概要欄を解析する**。ルーン（9枠すべて）、サモナースペル、タイムスタンプ（キルのタイミング）を抽出する。動画本体は取得しない。概要欄に書かれていない情報は、画面から手動で補えるようにする。
- **Phase 2B/3：手動入力ベース（2026-11-19 に方針変更。仕様書 DEC-018）**。当初は映像の画像認識を予定していたが、YouTube の書面による事前許可なしに映像は取得・解析できないため（下の「映像解析の規約調査」）、行わない。自動取得（概要欄）の項目も含めて、全項目を手動で入力・修正できるようにする。ウェーブのプッシュ・プルは、自動取得ができない可能性が極めて高い項目として、手動入力のみ。ワンボタンで記録する入力画面にする（動画の自動移動は、手触りが悪く削除した。バックアップは `backup/auto-skip-wave-editor`、Phase 2 終了宣言時に削除）。

## 映像解析の規約調査（2026-11-18）

**結論：YouTube から映像を取得してフレームを解析することは、YouTube の書面による事前の許可なしにはできない。** 根拠：利用規約（2023-06-01 発効）の「アクセス、複製、ダウンロード…を禁止（本サービスが承認、または YouTube と権利者が事前に書面で許可した場合を除く）」「自動化された手段（ロボット、スクレーパ等）でのアクセスの禁止」、デベロッパーポリシー III.E.1.a（audiovisual content の download / cache / store の禁止）、III.E.6（scrape の禁止）、III.I.7（映像・音声の分離の禁止）、III.I.14（API 以外の技術でのアクセスの禁止）。埋め込みプレーヤーからは、フレームを取得できない（取得できても III.I.6 に反する）。

取り得る道：(B) YouTube への書面許可の申請（API コンプライアンス監査、`support.google.com/youtube/contact/yt_api_form`。見込みは不明）、(C) 自分で用意した映像を解析（規約の問題なし）、(E) 映像を解析せず、概要欄と手動入力のみ。投稿者の許諾や CC BY のライセンスは、著作権の許諾にはなるが、YouTube の「アクセス手段」の制限は解消しない（私の調べでは）。無許可の取得・解析は進めない。

保存期限（30日）については、上記「YouTube データの保存期限」を参照（仕様書 DEC-016）。

## 手動入力ベースの検討メモ（2026-11-19）

- **鮮度**：手動入力も、動画の行と一緒に21日で消える（DEC-017）。パッチで古くなる前提。
- **編集権限**：仲間内で使う想定。編集できるのは、アドミンと、アドミンが許可したスーパーユーザーだけ。仲間内のメモツールの様相になる可能性がある。ログインの仕組みが必要で、HTTPS 化が前提（TBD-008）。
- **入力の手間**：できる限り簡略化する。ウェーブは番号順に1ボタン（またはキー）で記録するだけで、動画の再生時間は持たない（DEC-024）。動画を自動で動かす機能は、試したが手触りが悪く削除した（バックアップは `backup/auto-skip-wave-editor`、Phase 2 終了宣言時に削除）。
- **プッシュ・プルの向き**：この動画の「自分側」のチャンピオンから見た向きで記録する。判定の目安を、仲間内でそろえる必要がある（TBD-009）。
- **プレーヤーの制御**：YouTube の IFrame Player API は、ビルド編集のタイムラインが再生位置を読むときだけ使う（取得のみ。シークや一時停止は行わない）。プレーヤーの標準の再生機能や見た目は変えない（規約 III.I.6 に反しない範囲）。**フレームの内容は、読まない。**

## Phase 2B の検討メモ

- 映像の取得方法：仕様書では、動画のダウンロード、ミラー、再配布を禁止している。フレームの取得方法は、実装を始める前に規約の面から確認すること。
- HUD の位置：チャンネルごとにオーバーレイの位置や解像度が異なる。まずは Challenger Replays のレイアウトを基準に、切り出す座標を決める。
- 判定方法：Data Dragon のアイテムアイコン（ドラン系、カル、ダークシール、ポーションなど、`game_assets.json` の `starterItems`）とのテンプレートマッチングから試す。
- 現状：スタートアイテムは、概要欄の `Starter Items:` 行と手動登録のみ（`Build:` 行からの推定は廃止）。画像認識の結果が入るまで、多くの動画で「未確認」と表示される。
- 推定値の扱い：画像認識の結果は信頼度とあわせて保存し、確定情報と区別して画面に表示する（仕様書 4.4）。
